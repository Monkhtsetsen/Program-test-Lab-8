## 3. Хэсэг B — Mutation Testing

Тестүүд алдаатай кодыг илрүүлж чадаж байгаа эсэхийг шалгахын тулд эх кодод зориудаар гурван өөрчлөлт хийж туршсан. Мутаци бүрийн дараа эх кодыг сэргээсэн.

| Мутант   | Кодод хийсэн өөрчлөлт                                  | Унасан тест                                                                                |
| -------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| Mutant 1 | Идэвхгүй оюутны шалгалтыг комментолсон                 | `register_inactiveStudent_returnsError`, `register_errorCases_returnsExpectedError` (S009) |
| Mutant 2 | `repository.saveRegistration()` дуудалтыг комментолсон | `register_activeStudent_returnsOK`, `register_emailFails_registrationStillSucceeds`        |
| Mutant 3 | `courseId == null` шалгалтыг устгасан                  | `register_nullInput_throwsException`                                                       |

### Mutation 1-ийн үр дүн

```text
Tests run: 10, Failures: 2, Errors: 0
BUILD FAILURE
```

Идэвхгүй оюутны шалгалтыг устгаснаар A3 болон A8-ийн идэвхгүй оюутны тохиолдол алдаа илрүүлсэн.

### Mutation 2-ийн үр дүн

```text
Tests run: 10, Failures: 2, Errors: 0
BUILD FAILURE
```

Бүртгэл хадгалах дуудлагыг устгаснаар A1 болон A5 тестүүд алдаа илрүүлсэн.

### Mutation 3-ийн үр дүн

```text
Tests run: 10, Failures: 1, Errors: 0
BUILD FAILURE
```

`courseId`-ийн null шалгалтыг устгаснаар A6 тест алдаа илрүүлсэн.

### Mutation Testing-ийн дүгнэлт

Гурван мутацийн бүх тохиолдолд тестүүд алдааг илрүүлж, `BUILD FAILURE` үр дүн гаргасан. Энэ нь бичсэн тестүүд зөвхөн амжилттай ажиллагааг шалгаад зогсохгүй тодорхой алдаатай өөрчлөлтүүдийг илрүүлэх чадвартайг харуулж байна.

## 4. Ерөнхий дүгнэлт

Mockito mock объект нь бодит хамаарлыг орлуулж, тестийн явцад түүний ажиллагааг удирдах боломж олгодог. Харин fake объект нь бодит объектын зарим үйл ажиллагааг хялбаршуулсан байдлаар өөрөө хэрэгжүүлдэг. Гадаад систем, өгөгдлийн сан, имэйл үйлчилгээ зэрэг хамаарлыг тестлэх үед mock ашиглах нь тохиромжтой. Харин тестэлж буй классын үндсэн бизнес логикийг mock хийхээс зайлсхийх хэрэгтэй. Учир нь тухайн логикийг mock хийвэл бодит ажиллагааг шалгаж чадахгүй. `verify()`-ийг хэт их ашиглавал тестүүд хэрэгжүүлэлтийн жижиг өөрчлөлтөд мэдрэмтгий болж, шаардлагагүйгээр эвдрэх эрсдэлтэй. Иймээс зөвхөн чухал харилцан үйлдэл болон үр дүнг шалгах нь зүйтэй. Энэ лабораторийн ажлаар Mockito ашиглан mock объект үүсгэх, method дуудалтыг шалгах, аргумент барих болон mutation testing хийх чадвар эзэмшсэн.
